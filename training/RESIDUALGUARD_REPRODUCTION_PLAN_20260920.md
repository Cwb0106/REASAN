# 在 REASAN 环境中复现 ResidualGuard

核对日期：2026-09-20。依据仓库内 `ICRA2027_ResidualGuard.pdf` 与当前源码。
本文是实现路线和差距核对，不代表已经完成训练或得到论文结果。

## 1. 先确定复现目标

第一阶段在已有 Go2 环境中验证方法效果：遇到真实碰撞威胁时修正速度，安全擦身时尽量保持外部指令，同时保持任务进度。

论文使用 Go2-W，当前仓库使用普通 Go2。第一阶段属于 Go2 平台上的方法迁移；论文的 4 m/s 性能和表格数值需要 Go2-W 模型、对应步态策略、共同的指令协议和配对场景才能比较。

## 3. 方法中必须保留的机制

### 残差接口

```text
raw_residual = S_delta * actor_action
filtered_residual[t] = (1 - beta) * filtered_residual[t-1] + beta * raw_residual[t]
executed_command = clip(nominal_command + filtered_residual, command_limits)
effective_correction = executed_command - nominal_command
```

仅平滑残差；名义指令不经过该平滑器。`S_delta` 是量纲转换，不是硬残差边界。奖励、干预指标和低层输入需要区分原始残差、平滑残差、裁剪前命令与实际执行命令。

当前 `_pre_physics_step()` 将网络动作直接当作绝对速度。简单改为相加会改变已有权重的意义，不能把 `filter_1` 当作已训练好的残差策略。

### Ray-DCR

按论文式 (4)–(8) 实现独立的批量张量函数：

1. 用当前实测体速度扩张椭圆包络；同一状态下不同候选命令共用此包络。
2. 将中心到表面命中的二维点仿射映射至参考圆，计算边界间隙与径向、切向方向。
3. 候选平移速度与障碍速度共同确定相对运动；候选角速度的显式旋转项只进入径向分量。
4. 计算 `B = radial_velocity + alpha * affine_gap + tangential_allowance`。
5. 对负裕量进行饱和映射，无效射线先清零，再循环最大池化和加权聚合，得到 `[0, 1]` 风险。

必须在同一动作前状态计算 `R_nom = R(s_t, u_nom)` 与 `R_cand = R(s_t, u_exec)`。候选风险进入奖励，名义风险控制指令保持相关项及残差正则的门控。推理时不计算 Ray-DCR。

代码中的多中心射线距离不能直接视为统一机体中心的距离：应确认命中点、原点、方向、对象编号和有效性一致，再构造 `p_i`。无命中距离裁剪后的有限值不能当作真实障碍。

### 响应编码器和优化

论文将 5 帧、每帧 57 维历史送入 128–64 MLP，输出三维线速度估计和 L2 归一化的八维响应 latent。速度估计与射线特征等进入 LSTM，响应 latent 在 LSTM 后与输出拼接。编码器通过速度估计和下一步响应预测的 Smooth-L1 损失单独训练。

Go2 的关节与动作维数不同，需要明确定义本平台历史内容和归一化，不能直接补零成 57 维并声称一致。历史只包含当前决策可用的数据，终止环境的历史、LSTM 状态和残差状态都要清零。

PPO 使用 rollout 时记录的响应上下文，避免编码器更新改变旧样本的输入。名义风险门控的正则约束动作分布的原始均值，单独加入 actor loss，不混入奖励与 return；排除无效和终止样本。

| C：响应编码器 | 历史缓冲、速度头、响应预测头、独立优化器、rollout 存储及 checkpoint | 完整控制策略与去除切向项、去除响应 latent 的消融 |

| E：轮足高速结果 | Go2-W 资产、轮关节执行器、速度跟踪策略及训练配置 | 共享轮足底层控制器下的 2/3/4 m/s 配对评估 |

第一阶段建议从 1.0–1.5 m/s 开始，确认跟踪与避障稳定后提高速度。这是 Go2 适配建议，不是论文参数。当前环境速度上限为 `[2.5, 1.5, 3.0]`；不能仅修改上限就假设能够稳定达到 4 m/s。

感知复现时，论文使用 8 帧、30×180 网格、4 m 范围，并显式输入相对位姿和时间信息；当前 REASAN 射线观测以 3 m 归一化。射线表示与范围的改变需要同步适配策略训练和评估。真值射线实验与预测射线实验分开报告。

## 5. 实现入口及容易出现的错误

| 现有入口 | 应新增或扩展的内容 |
| --- | --- |
| `go2_lidar/go2_lidar/tasks/go2_filter_env.py` | 独立残差任务；动作前风险缓存、命令处理、奖励、历史及 reset |
| `go2_lidar/go2_lidar/tasks/go2_filter_env_cfg.py` | 残差尺度、风险参数、观测定义、平台参数 |
| `go2_lidar/go2_lidar/tasks/__init__.py` | 注册新任务，保留原任务用于基线 |
| `rsl_rl/rsl_rl/modules/actor_critic_recurrent_ray.py` | 独立 residual actor/critic 与响应编码器 |
| `rsl_rl/rsl_rl/storage/rollout_storage.py` | 保存名义风险、响应上下文、监督目标及有效掩码 |
| `rsl_rl/rsl_rl/algorithms/ppo.py` | 独立 PPO 扩展：门控 actor 正则、辅助优化 |
| `rsl_rl/rsl_rl/runners/on_policy_runner.py` | 新 runner 或明确的类选择；编码器训练与保存/加载 |
| `scripts/train_filter.py`、`scripts/play_filter.py` | 新训练、播放和有限步数评估入口 |

需要处理三个现有代码细节：

- Runner 目前删除配置中的 `class_name` 并硬编码策略类与 PPO，单改配置不会切换到新实现。
- IsaacLab 的 `step()` 顺序为动作处理、物理步、终止与奖励、reset、下一次观测；现有 TTC 在观测阶段计算。新风险应在动作前成对计算并缓存，不能混用动作前后的状态。
- 原环境在发出低层控制输入后更新名义命令。奖励和记录需要保存本次决策使用的 `u_nom`，避免实际动作与下一次指令错配。下一步响应监督目标要在自动 reset 前保存，或通过有效掩码排除跨 episode 样本。

## 6. 如何判断“复现出效果”

共同条件：固定底层步态权重、机器人参数、场景种子、外部名义指令生成规则、速度范围和感知来源。基线与新方法使用配对场景。至少比较 Nominal、REASAN-Filter、独立训练的 Residual-TTC、ResidualGuard。

优先做三组场景：迎面碰撞威胁、安全擦身、移动障碍横穿；随后增加静态柱林和动态走廊。Threat / nominal-safe 标签通过单独执行名义策略的接触结果确定，不用 Ray-DCR 自己给自己标注正确性。

- **SR**：无碰撞完成率；明确机器人任意部位的障碍/墙体接触、跌倒、边界越界、超时及控制中止规则。
- **IC**：按时间加权的 `norm(D^-1 * (u_exec - u_nom), 2)`；所有方法共用归一化尺度，包含失败轨迹直到首次终止。
- **TP**：纵向起点到终点的归一化推进比例，裁剪至 `[0, 1]`；同样包含失败样本。
- 轨迹和时序图：机器人/障碍位置、名义与执行命令、有效修正、风险、接触及终止原因；配套视频展示相同场景。

Go2 适配实验可预先固定 `D = diag(2.5, 1.5, 3.0)`；论文使用 `diag(4.0, 1.7, 2.5)`。不同尺度下的 IC 数值不能直接横向比较。收益判据是保持或改善 SR/TP 的同时降低不必要干预，不能只报告 IC 降低。
